# 验证说明

Agenthub 区分自动化 fixture 验证、独立浏览器验证和真实 Kimi 调用。自动测试无需登录或消耗模型额度；真实验收是显式的单独操作，不进入 CI。

## 可复现检查

```bash
npm ci
npm run check
npm run build
npm test
npx playwright install chromium
npm run test:browser
npm run test:example
npm run test:example-browser
```

| 检查                  | 验证范围                                                                         |
| --------------------- | -------------------------------------------------------------------------------- |
| TypeScript + Prettier | 类型检查与统一格式                                                               |
| 发布文件检查          | 忽略运行数据、源码调研档案和测试证据，检测候选文件中的私人路径及高置信度凭据格式 |
| 自动测试              | 状态机、ACP、数据、权限、API、持久化与恢复                                       |
| Playwright 工作台     | 首次配置、分工编辑与确认、审批、取消、反馈、历史、文件与执行详情                 |
| 示例 node:test        | 任务列表示例的纯逻辑与持久化数据契约                                             |
| 示例独立浏览器        | 页面新增、完成、删除、优先级修改、组合筛选及刷新持久化                           |

自动测试使用临时 SQLite、隔离目录和模拟 CLI。浏览器测试在端口 4318 启动独立 fixture 服务；生产端口和真实账号不参与。请避免同时启动两套浏览器测试。

CI 配置为 macOS/Linux、Node.js 22/24。提交后的 CI 结果以 GitHub Actions 实际运行为准，本地检查通过不能替代尚未执行的 CI。

## 首版真实验收

首版在本地以 Kimi CLI 2.1.1 完成了两轮实际交付：先实现可持久化任务列表，再根据反馈添加优先级和组合筛选。每轮执行与 review 使用独立 Kimi 会话。原始任务、会话 ID、账号状态和导出证据保留在本地，不进入开源仓库。

真实试跑发现并修复了以下问题：

1. Kimi 的原生 plan/ExitPlanMode 会尝试继续执行自己的计划。改为只读工具白名单，让 Agenthub 管理外层确认与调度。
2. 原生审批回答后的旧 Task 引用可能重新恢复待处理提示。同步更新活动引用并拒绝失效或重复答案。
3. 工具流增量逐条保存导致重复日志和响应延迟。改为按调用聚合、250 ms 批量持久化，并在阶段结束刷新。
4. 新额度接口返回比例对象，原有解析只读取短窗口。兼容 usage/usages/limits 的新旧格式，并保留未知状态。
5. 多实例启动不应改写另一个实例的任务。增加 SQLite 服务租约，成功监听后才恢复中断记录。

模型对优先级功能的 review 曾判定通过，但独立浏览器验收发现页面缺少修改已有任务优先级的入口。验收阶段另行补齐选择器、保存与筛选更新，并加强实现/审查提示，明确区分纯模块函数、假 DOM 和真实页面交互。这项补修不归为模型最初交付的结果。

示例现保存在 `examples/kimi-acceptance/`，含 43 个 node:test 用例和 9 项独立浏览器检查。它可以无需 Kimi 重复验证。

## 执行详情

验证结构化参数、结果、文件差异、状态更新不清空输出、同一工具 ID 在不同会话隔离、截断提示、agent 主动返回的思考事件，以及失败、取消和服务重启中断的状态。

浏览器覆盖运行中到已完成的实时更新、参数/输出展开、会话切换、搜索、状态筛选、导出文件内容、Escape 关闭、刷新回看、旧记录兼容与 50 条分页。真实旧任务也在本地回看验证；历史未采集字段不补造。

## 开源整理

前端按页面、组件及共享 API 拆分；统一 Prettier 格式；启动脚本不依赖私人 Node 路径；浏览器使用显式配置、Mac 已安装 Chrome 或 Playwright Chromium。新验收项目位于运行数据目录，与仓库内示例分离。真实验收与截图脚本输出到被忽略的 `artifacts/`。

README 的演示截图使用浏览器测试 fixture，显示中立项目路径，不包含用户任务或账号数据。可在生成文档截图时显式设置：

```bash
AGENTHUB_CAPTURE_DEMO=1 npm run test:browser
```

## 真实验收命令

```bash
npm run dashboard
npm run test:live
```

该命令会消耗模型额度、自动确认它创建的验收计划并修改验收目录。未知原生权限请求会停止脚本，留下任务供工作台处理，不授予持续或无限权限。原始证据写入 `artifacts/live-acceptance.json`。默认目标为 `.agenthub/acceptance-project/`；执行前检查使用的数据目录与任务范围。

## 边界

当前只验证了 Kimi 实际接入。其他 agent、Windows、Mac 安装包、跨模型 benchmark 和跨账号调度尚未完成。文件预览不是备份或操作系统沙箱。通过 review 不保证不存在缺陷；涉及页面功能时仍需要实际浏览器证据。
